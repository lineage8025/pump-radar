## 限制段

1. **Parkinson 型未修正極值估計量、零漂移假設**（`program.md` §4 預登記的已知偏誤，
   run1~4 持續適用，本次不例外）：`(max(high)−min(low))/close` 假設零漂移，
   **單邊趨勢行情會讓 range 系統性偏高，把「有方向的趨勢延續」誤記成「振幅擴大」**。
   這正是網格交易最怕的情境（`docs/RND_BACKLOG.md` 方向一的核心風險）：本表所有
   「高分位桶振幅大」的數字，都可能有一部分其實是「那段時間在趨勢中」而非「在震盪中
   來回擺盪」。**Yang-Zhang／Garman-Klass 交叉驗證仍未做**（§4.1 已放行，本次未執行，見誘惑清單）。
2. **去叢集實際上退化成「固定 UTC 時刻的日格點」，不是隨機時點——run1~3 的措辭不精確。**
   去叢集規則是「索引 +96 根」的貪婪步進，而分析窗內候選列是連續的，所以每個標的每天
   恰好取一筆、且全部落在同一個時刻：ORIG 全部 00:00、EXT 有 11930 筆在 01:15／830 筆在 00:00。
   因此 Q2' 的「隨機時點對照組」其實是**固定時刻對照組**，而 event 分佈在全部 24 個 UTC 小時
   （最密集在 12~14 UTC，各 133~155 筆）——兩組的起算時刻分佈系統性不同。
   **已做敏感度檢查**：同期同分桶下 00:00 相位 +2.760pp vs 01:15 相位 +2.784pp，差 0.024pp，
   影響可忽略；理由也講得通——T=24h 涵蓋完整日內週期，對起算時刻本來就不敏感。
   但**短 T（1h/4h）對起算時刻一定敏感**，本次未量化（Q1 的跨桶比較因為所有樣本共用同一
   個格點而自動抵消，Q2' 的 event vs 對照則沒有這層保護，只是本次只在 24h 上比較）。
3. **10 個標的每天在同一個時間戳被取樣，跨標的相關性是結構性的、不是偶發的。**
   逐週區塊 bootstrap 把同一週的所有標的綁在一起重抽，部分處理了這個問題；
   但有效自由度仍遠低於表面 n（EXT 的 12760 筆實質上是 1276 天 × 10 條高度共動的序列）。
4. **2023-03-24 12:45~13:45 UTC 全 10 標的同缺 5 根 K 棒**（交易所端）：
   （a）使日格點相位在該日之後由 00:00 移到 01:15（影響已量化，見上）；
   （b）「24h 窗」實作上是「96 根」而非嚴格 24 小時，只有跨越該缺口的那一筆樣本的
   實際窗長是 25.25 小時。單筆影響，未特別處理。
5. **跨標的 4h 窗去重的 tie-break 是任意的。** 多個標的在**完全相同的時間戳**觸發時，
   「同 4h 窗僅計首發」保留哪一筆取決於排序穩定性——實測：同一份 P1 期資料，
   主探針與補充探針保留的 1266 筆中有 **112 筆（8.8%）是不同標的**（時間戳集合與 4h 窗
   集合完全相同，只是代表標的不同），使分桶 n 有 ±2 級的任意性（例如 P1 最低桶 26 vs 24）。
   **不影響任何 CI 結論**（所有 CI 都寬到這種差異無關緊要），但 n 卡在 30 門檻附近時
   這個任意性會變得要緊——本次 EXT 的 42／51 距門檻夠遠，結論不受影響。
   這是 run2/run3 既有實作繼承下來的性質，本次只是量出來。
6. **延長窗口引入了新的存活偏誤（本次新增的代價，必須記）**：10 個標的是**2026 年仍在
   交易、且被選進 `docker-compose.yml` 的 PAIRS**。把窗口回推到 2023-01，等於用
   「後見之明選中的存活者」去看 2023~2024 年——當年真正的候選集合裡那些後來下市／
   流動性枯竭的標的完全不在樣本內。窗口越長這個偏誤越重，這是延長窗口**必然付出的
   代價**，不是可以修掉的 bug。P1 的效應量（+3.671pp）因此不能直接當成「當年即時可得
   的區別力」。
7. **極端壓縮兩桶的 event 100% 是 A 級**（42/42、51/51）：`bbw_pct` 觸發當下 <0.10
   幾乎必然使前一根 `bbw_pct ≤0.25` 成立，這是分級定義的機械後果，不是實證發現。
   所以那兩桶的「event vs 對照」等同「A 級 vs 對照」，沒有 B 級可比。
8. **延長窗口版本一律是事後延長**，主結果永遠是 ORIG（§4.2 第 2 條）。本日誌所有 EXT／P1
   數字都已標明。

## 最強反駁

1. **「兩個不重疊時期都成立」離「排除 regime 混淆」還有距離。**
   2023-2024 與 2025-2026 都是同一個加密貨幣市場、同一批高度共動的標的、同一個
   宏觀利率／流動性大週期的不同片段。若驅動 `bbw_pct`→振幅關係的是「加密市場的
   波動聚集結構」這個貫穿全期的性質，那**任何**時期切法都會各自成立——這不叫
   「效應穩健」，這叫「效應是這個市場的結構性特徵」。真正能證偽 regime 混淆的
   對照是**不同資產類別**（股票／外匯）或**不同市場結構時期**（例如 2018 前），
   本次做不到。所以誠實的狀態是：**run1 最強反駁第 1／3 點被削弱，不是被排除。**
2. **更根本的：Q1「有區別力」很可能只是波動聚集的機械性重述，不是新資訊。**
   `bbw_pct` 是 BBW 在 30 天滾動窗的百分位，高分位＝**近期波動剛放大**。
   「近期波動大 → 未來 24h 振幅也大」正是 GARCH 持續性的教科書預測
   （`RESEARCH_BBW_VOLATILITY.md` 第二節）。本次三窗口一致、時期分層一致、
   市值分層一致（run4 Q1''）——這些「穩健」恰恰是**教科書效應該有的樣子**。
   因此 Q1 的正確定位是「確認了已知的波動持續性在這個度量、這個頻率、這個市場上
   成立」，**不是「發現了 pump-radar 特有的 edge」**。對 `docs/RND_BACKLOG.md` 方向一
   的實際價值是：區間寬度可以照分桶事前定，但那個「可預測性」的來源是公開的
   統計常識，沒有任何專屬優勢，也不構成任何交易主張。
3. **Q2'' 的「無差異」有一部分可能是我自己設計的對照組造成的。**
   對照組是同桶的日格點樣本，而 event 是「突破上軌 + 放量」的時刻——兩者除了
   `bbw_pct` 相同之外，**在時間軸上不是同一種東西**（見限制段 2：起算時刻分佈不同；
   另外 event 必然發生在一根大陽線之後，對照組則是任意一天的固定時刻）。
   「配對」只配了 `bbw_pct` 一個維度。若還有其他系統性差異同時往兩個方向拉，
   仍可能互相抵消——這正是 run2 Q2 被 run3 修正過一次的同一類問題，本次只是把
   配對維度從 0 個加到 1 個，不代表已經乾淨。
4. **本次「n 過門檻了」這件事本身是延長窗口換來的，而延長窗口是為了讓 n 過門檻。**
   雖然 §4.2 的程序（先登記窗口、全網格重跑、雙報、時期分層）已經把 p-hacking 的
   空間壓到很小，而且**結果是陰性的**（極端桶依然無差異）——陰性結果讓「為了好看
   而延長」的疑慮基本消失——但如果當初結果是陽性的，這個程序的說服力會比現在弱得多。
   記在這裡供未來對照：**這次能安心引用，很大程度是因為它沒給我們想要的答案。**

### 發現

1. **三方一致，Q1 效應不是估計量選擇的產物。** §4.1 的判準是「兩者不一致 →
   `inconclusive`」；本次 GK 與 YZ 不只彼此一致，也與已凍結的 Parkinson range 主結果
   方向一致（皆正、皆顯著），因此依約束③判定為 `supports`。
2. **漂移修正（YZ 有做、GK 沒做）在這個檢定尺度上看不出差異**——這是本次最直接回應
   限制段疑慮的發現：如果「最高桶樣本剛好是趨勢明確的時段、被 Parkinson range 系統性
   高估」是驅動 Q1 效應的主因，理論上做了漂移修正的 YZ 應該相對 GK 出現可辨識的差距
   壓縮；實測 GK 與 YZ 的 24h 差距點估計只差 0.0169pp（+2.1545 vs +2.1714，YZ 甚至
   略高不低），CI 幾乎完全重疊。**這不能證明「Q1 效應完全與漂移無關」**（見最強反駁），
   但排除了「漂移是主要驅動力」這個特定版本的疑慮。
3. **公式正確性已用合成資料驗證，且截尾從未觸發**：這是方法論衛生檢查，不是實質發現，
   但值得記錄——本次交叉驗證的可信度建立在「公式沒寫錯」這個前提上，合成資料測試
   （常數價格 → 0；已知 sigma 的隨機漫步 → 同量級）與截尾觸發次數統計（0/21800）
   都支持這個前提。

### 限制段

1. **Parkinson 型未修正極值估計量、零漂移假設**（`program.md` §4 預登記的已知偏誤）——
   仍是主結果（Parkinson range）本身的限制，不因本次交叉驗證而消失；本次只是提供了
   額外證據支持「這個限制在聚合分位數層級沒有推翻 Q1 的方向性結論」，**不等於「主結果
   的漂移偏誤問題已解決」**——主結果的公式本身沒有變。
2. **GK 與 YZ 高度相關，不是兩個真正獨立的視角。** 兩者都是 OHLC-based range estimator
   家族成員，數學結構相近（YZ 的 Rogers-Satchell 分量與 GK 有共同祖源），本次觀察到
   的「幾乎重疊」部分反映的可能是**估計量家族的相似性**，不是「兩種獨立方法各自驗證
   出同一個真相」那麼強的證據。真正獨立的交叉驗證需要質性不同的方法（例如已實現波動率
   用更高頻資料重建、或跳空/微結構雜訊模型），但那些不在 §4.1 放行的兩個具名估計量
   之列，本次不做（掃第三個估計量＝事後挑量尺，需走 §5 或另行人類裁決）。
3. **本次只在聚合分位數（p50/p80/p95）層級比較，沒有逐樣本比較 GK/YZ 與 Parkinson range
   的差異。** 「漂移修正看不出差異」的結論是基於分桶聚合後的分位數重疊，不排除在
   **個別高度趨勢化的樣本**上兩者差距很大、只是在幾百筆樣本取分位數時被平均掉——
   若要精確回答「哪些樣本受漂移影響最大」需要逐樣本相關性/差異分析，本次未做。
4. **10 個標的高度共動、去叢集後仍是「固定 UTC 時刻的日格點」**（run5 限制段 2 已記錄
   的方法論瑕疵，本次沿用同一套取樣，問題原樣繼承，不重複展開）。
5. **窗口只用 ORIG（2025-01~2026-06），未對 EXT／P1 重做 YZ/GK。** §4.1 約束②要求
   主結果永遠是凍結網格版，沒有要求 YZ/GK 必須覆蓋所有窗口；本次選擇只做 ORIG 主窗口
   （run5 建議的範圍）以維持工作量可控（§2「寧缺毋濫」），若之後 EXT/P1 的 Q1 效應
   本身受到新的質疑，才值得再花一輪把 YZ/GK 覆蓋過去。

### 最強反駁

1. **「三方一致」有一部分是同一套資料管線與同一組樣本點造成的必然結果，不是三個獨立
   證據源。** GK、YZ、Parkinson range 三者都是同一批 5450 個取樣點（同樣的
   `bbw_pct` 分桶、同樣的去叢集、同樣的 K 棒資料）套三個不同公式算出來的——如果驅動
   Q1 效應的是「這批樣本本身在高低桶之間有真實的日內波動差異」（不管用哪種量尺去量都
   量得到），那三個估計量當然會一致，這**不是**在問「Q1 效應存不存在」這個問題上
   提供新資訊，只是在問「這個效應是不是某個特定公式的度量假象」這個更窄的問題上
   排除了否定答案。真正獨立的交叉驗證需要不同的資料源（例如更高頻的資料重建已實現
   波動率）或完全不同的統計方法，本次做不到。
2. **YZ 沒有壓低差距這件事，可能是因為本次比較的兩個桶（最低與最高分位）恰好在
   「趨勢污染程度」上沒有系統性差異，而不是因為漂移本身在這個市場不重要。** 若
   `bbw_pct` 最高桶剛好同時是「波動大」與「趨勢明確」高度相關的時段（兩者在真實市場
   常常同時發生——強趨勢行情通常也伴隨高波動），那麼 GK 與 YZ 都會同時被「真實高波動」
   與「趨勢污染」兩個因素推高，YZ 的漂移修正在**這個特定情境**下可能修正力道不足以
   顯現出差距——這與「漂移不是問題」是兩回事，只是本次的檢定設計沒能把兩者拆開。
3. **這次交叉驗證回應的是限制段的疑慮，沒有回應 run5 最強反駁第 2 點**（Q1 效應
   可能只是波動聚集/GARCH 持續性的機械性重述，不是 pump-radar 特有的 edge）——
   換了三個不同的波動估計量，如果它們衡量的都是同一個「近期波動大 → 未來波動也大」
   的教科書效應，那三方一致本身**不構成**「這是新發現」的證據，反而更像是「這個
   教科書效應在三種量尺下都同樣成立」，與 run5 的定位一致：Q1 的正確描述仍是
   「確認了已知的波動持續性」，不是「發現了獨家 edge」。

### 限制段

1. **Token scope 未經驗證**：`archive_issue()` 假設現有 `GITHUB_DISPATCH_TOKEN`
   （目前只用於 `repository_dispatch`）也涵蓋建立 issue 所需的 `issues:write`
   （或 `repo` scope，視 PAT 是 classic 還是 fine-grained 而定）。這是本次最大的
   不確定性，sandbox 裡沒有這個 token 也看不到它的權限設定，**只有人能確認**；
   若 scope 不足，功能靜默失效但不影響其他任何東西（try/except 包住）。
2. **Label 需要人類手動建立**（或接受無 label 降級）：`daily-pulse-archive` 目前
   不存在，程式已處理 422 自動重試不帶 label，但那樣所有 issue 都混在
   `gh issue list` 的預設輸出裡，篩選性下降。
3. **未實際執行過**：只做了 `py_compile` 語法檢查與人工邏輯核對，沒有整合測試——
   這在 tooling 車道的既有慣例內是合理的（run4 的 `fetch_klines.py` PR 也是類似
   審閱深度），但比 probe 車道「跑出實際數字」的驗證強度弱，誠實記錄。
4. **這個變更會讓 issue 累積速度變成「每個有內容的日報一則」**，若日後 forward
   量增加、觸發更頻繁，issue 列表可能變得龐雜——PR 說明未提出保留期或封存機制，

1. **就算合併，也不足以讓迴圈真的「覆盤 forward」——只是把資料搬到看得到的地方。**

   而 agent 沒有能力在本次驗證這個假設，這是把賭注押在一個未經檢驗的前提上，
