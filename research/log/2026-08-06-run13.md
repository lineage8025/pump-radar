### 4.2 【本輪唯一的發現】「5 格」不是 seed 穩定的計數

run 8 §8.2 宣稱「未調整 95% CI 不含 0 者 **5 格**」。復算結果：

| bootstrap 設定 | 未調整顯著格數 |
|---|---|
| `boot=20,000`，13 次獨立重抽（12 seeds ＋ Part A 的 seed 4242） | **4 格 ×1、5 格 ×9、6 格 ×3** |
| `boot=400,000`，1 次 | **5 格**（且與 run 8 是**同一組** 5 格） |

原因是兩個**刀鋒格**——它們的 CI 端點落在 0 的 ±4e-4 之內，而該端點的蒙地卡羅雜訊
（表 4.1.3）正是 1e-4 量級：

| 格位 | 相關端點 | 跨 13 次重抽的範圍 | `boot=400,000` | 判顯著次數 |
|---|---|---|---|---|
| `[0,0.05)` × 24h | `lo95` | **−0.000057 ~ +0.000389** | +0.000114 | 12 / 13 |
| `[0.75,1.0]` × 1h | `hi95` | **−0.000033 ~ +0.000219** | +0.000047 | 3 / 13 |

（run 8 自己報的 `[0,0.05)`×24h 未調整 CI 就是 **[+0.0001, +0.0319]**——下界 +0.0001，
與本輪量到的雜訊同量級。這不是 run 8 算錯，是那格本來就貼在零線上。）

**這個發現改變了什麼**：
- **對判準：什麼都沒改變。** 「5 格」是描述性中間量，`RND_BACKLOG` 方向二的三個結局
  完全不依賴它——結局①看的是「調整後有沒有任何一格顯著」，結局②看的是經濟門檻。
- **對紀錄：必須寫下來。** 日後任何人引用「Q10 有 5 格未調整顯著」時，該數字的
  正確講法是「**在 `boot=400,000` 下是 5 格；在預登記的 `boot=20,000` 下是 4~6 格，
  其中 2 格是零線上的刀鋒格**」。

### 4.4 Part B — 上游層獨立驗證（完全獨立的資料路徑）

run 8 的 `A`/`B` 來自 **1m** K 線的對數空間路徑重建。本輪改由 **15m** K 線直接取極值重算：
`A = max(high[t+1..t+T])/P0 − 1`、`B = 1 − min(low[t+1..t+T])/P0`。
兩者數學上應相等（15m 的 high 就是其涵蓋的 1m high 的極大值），但**經過的程式碼、
資料檔、時間解析度完全不同**——這是本輪最有價值的一段，因為它獨立於 run 8 的整套
路徑重建機制。

| T | max\|Δamp\| | mean\|Δamp\| | max\|ΔR_act\| | mean\|ΔR_act\| | `\|ΔR\|>1e-6` 的列數 |
|---|---|---|---|---|---|
| 1h | 1.807e-15 | 2.468e-16 | 1.711e-12 | 3.509e-14 | **0 / 9,010** |
| 4h | 1.860e-15 | 2.454e-16 | 8.515e-13 | 1.709e-14 | **0 / 9,010** |
| 12h | 1.783e-15 | 2.448e-16 | 4.141e-13 | 9.053e-15 | **0 / 9,010** |
| 24h | 1.783e-15 | 2.444e-16 | 1.654e-13 | 5.982e-15 | **0 / 9,010** |

`bbw_pct`（`from detector import add_indicators`，production `PARAMS` 唯讀複用）：
**max\|Δ\| = 1.110e-16、桶別不一致 0 / 9,010**。
（順帶完成 `program.md` §1.5 的完整性檢查：本輪實際載入的 `PARAMS` 為
`bb_window=20, bb_std=2.0, bbw_pct_window=2880, bbw_pct_min_periods=960, squeeze_pct=0.25,
vol_window=96, vol_z_min=3.0, cooldown_bars=16`，與 `CLAUDE.md`／`DETECTOR_PREREG` 一致。）

**錨點結構（逐標的，獨立由時間戳重算）**

| 量 | 結果 | run 8／預登記的要求 |
|---|---|---|
| 每標的錨點數 | **901**（10 標的全同） | 9,010 總數 ✔ |
| 索引間隔最小值 | **97 根**（眾數 97、最大 163） | 「間隔 ≥ 最大 T（96 根）」✔ |
| 24h 窗互相重疊次數 | **0**（10/10 標的） | 去叢集要求 ✔ |
| 相異相位數 | **96**（＝一天全部 96 個 15m 相位） | §4 操作化決定 1「相位輪轉」✔ |
| ISO 週數 | **131** | run 8 宣稱 131 ✔ |

（間隔最大 163 而非 97 的倍數，是因為探針的掃描規則是「候選被丟棄時 `i += 1`、
被接受時 `i += 97`」——丟棄連續發生時下一個錨點的相位會整段位移。本輪確認這不破壞

**`diag.tsv` 丟棄計數的守恆核對**：依上述掃描規則，應有
`錨點數 × 97 + 丟棄數 = 分析窗 [2023-01-01, 2025-07-01) 內的 15m 根數`。

`901 × 97 + 150 = 87,547`，而窗內實際根數 **87,547**——**10/10 標的精確守恆**。

## 5. 限制段

1. **本輪驗不到 `R_flip`（對照組本身）。** Part B 的獨立路徑只重建得出 `R_act`／`amp`；
   `R_flip` 需要 1m 逐根符號翻轉重建 200 次，用 15m 資料在原理上就做不到。
   換句話說 `ΔR = R_act − R_flip` **只有被減數被獨立驗證了**。
   緩和（但不是消除）：run 8 §4 決定 2 有一道**逐錨點執行期硬驗證**——
   翻轉機制在 `ε ≡ +1` 時必須逐位元重現由原始高低價直接算出的 `A/B`（9,010 × 4 全過）；
   而本輪 Part B 獨立確認了那個「被重現的目標值」本身是對的。
   ⇒ 翻轉機制的 `ε=+1` 分支已端到端驗證，**`ε≠+1` 分支仍只有 run 8 自己的 self-test 背書**。
2. **稽核不能證明「度量選得對」，只能證明「算得對」。** run 8 §10 反駁 4 界定的射程
   （R 對報酬短落後期自相關無感、只看得見窗口尺度的單擺形狀）**完全未被本輪觸及**，
   仍然是 Q10 否定結論的正確射程限制。
3. **承襲 `program.md` §4 的 Parkinson 漂移偏誤限制**：`A+B` 是未修正的極值型振幅估計量，
   單邊趨勢行情會讓它系統性偏高。run 8 §9 限制 1 進一步指出，能把 `ΔR` 推正的合成結構
   是**整段常數漂移**，故低分桶的正 `ΔR` 機制上可能純粹是 2023–2025 的單邊行情。
   **本輪的復算一字不改地繼承這個偏誤**——復算只保證算術，不保證度量無偏。
4. **shallow clone，無法從 git 歷史稽核憲章是否被改動**（`git rev-list --count HEAD` = 1，
   同 run 10/11 的已知限制）。本輪改以內容檢查替代：`PARAMS` 9 個鍵值、
   `TRADEABILITY_PREREG.md` §3.3 成本模型、`RND_BACKLOG.md` 方向二凍結網格與三種結局，
   與 run 8 日誌所引用者逐項一致。**這是嚇阻不是保證。**
5. **存活偏誤**（10 PAIRS 是 2026 年的存活者名單）與**錨點的缺口迴避偏誤**
   （命中缺 K 棒窗口的候選被丟棄，每標的 150 個）**原樣繼承**，本輪未量化亦未改善。
6. **`boot=400,000` 不是預登記值。** 預登記的是 `boot=20,000`；本輪跑 400,000 只用來
   **診斷**「5 格」計數的收斂位置，**不用來取代任何 run 8 的已宣告 CI**——
   §4.3 表格中 run 8 那一欄仍是 20,000 版。這是刻意的：提高精度重報 CI 會構成
   「事後換設定」，即使方向對結論有利也不做。
