## 為什麼是這條，以及為什麼不是別條

`docs/TRADEABILITY_PREREG.md` §2 的統一命題：**Q1 的振幅可預測性，扣掉成本後還剩什麼？**

Q1 已經四輪 `supports`、三估計量交叉驗證，是本專案唯一指向可交易性的入口。
但它只量了振幅的**大小** `(A+B)`，**從來沒量過振幅的形狀**。

而「大小」本身不決定任何策略的死活。同樣是 24 小時走了 5% 的振幅：

| 形狀 | 路徑 | 誰活 |
|---|---|---|
| 單邊走完 | 一路漲 5% 不回頭 | **長伽瑪**（雙向突破單）活，**短伽瑪**（網格）死 |
| 來回震盪 | 上下各 2.5% 反覆 | **短伽瑪**活，**長伽瑪**被雙邊停損磨死 |

**Q1 完全分不出這兩者。** 方向一（網格＝短伽瑪）在沒問過這個問題的情況下就直接跑了
Phase 1，結果是 748,200 episodes 換一個負號。這次先問形狀，再決定跑哪種結構。

## 度量：可捕獲趨勢比 R

對取樣點 t（`P0 = close(t)`），在其後 T 小時內：

```
A = max(high[t+1 .. t+T]) − P0        上行最大偏移，≥ 0
B = P0 − min(low [t+1 .. t+T])        下行最大偏移，≥ 0
振幅 = A + B                           （＝ Q1 的度量，直接可比）
R    = max(A, B) / (A + B)             定義域 [0.5, 1]
```

- `R → 1`：走勢單邊走完不回頭 → 趨勢持續 → **長伽瑪友善**
- `R → 0.5`：上下走得一樣遠 → 來回震盪 → **短伽瑪友善**

**符號翻轉不變性**（`TRADEABILITY_PREREG.md` §1.3 的硬性前置檢定）：
報酬序列整體乘以 −1 後，`A` 與 `B` 互換，`max(A,B)` 與 `A+B` 皆不變 ⇒ **R 不變**。
本度量與方向完全無關，**受理**。

## 對照組：隨機符號翻轉（不是隨機重排）

基準不能用「隨機時點」——那是 Q1 的對照組，回答的是別的問題。
本題的正確對照是**同一段路徑、打散方向結構、保留其他一切**：

> 取該 episode 的每根 1m 對數報酬 `r_i`，令 `r_i → ε_i · r_i`，
> `ε_i ∈ {−1, +1}` 等機率獨立抽取，重建價格路徑後重算 R。重複 **200 次**取平均得 `R_flip`。

為什麼是 sign flip 而不是 permutation：sign flip **完整保留 `|r_i|` 的時序**，
因此波動聚集、厚尾、日內週期全部原封不動——`R_actual − R_flip` 的差異
**只可能來自報酬符號的時序結構**（趨勢持續 vs 均值回歸）。
隨機重排會連波動聚集一起打散，而波動聚集正是 Q1 的效應來源，
把它一起破壞掉就混淆了「我在測什麼」。

統計量：**ΔR = R_actual − R_flip**。

## Kill criteria（三種結局預先寫死，避免事後編故事）

| 結局 | 條件 | 處置 |
|---|---|---|
| **① 無形狀** | 24 格中**無任何一格** ΔR 的 Bonferroni 調整 CI 不含 0 | **方向二終止**，並宣告：Q1 的振幅可預測性**不支撐任何方向中性交易結構**。這是本迴圈可交出的最有價值的否定結論 |
| **② 顯著但不夠大** | 有格位顯著，但最佳格位的可捕獲報酬 < **0.28%**（`TRADEABILITY_PREREG.md` §3.3 門檻） | 記 `weakens`，**不進 Phase 1**。統計顯著 ≠ 賺得到 |

可捕獲報酬的換算（預先定義，避免事後挑算法）：

```
可捕獲報酬 ≈ ΔR × E[A + B]
```

**這是上界，不是策略收益**——實際策略還要付出進場門檻、雙邊停損與滑價。
日誌必須明寫它是上界；上界都打不過 0.28% 就不必再往下做。

## 為什麼這條特別適合每 2 小時一輪的排程

它是**確定性、耗時、無假設**的工作：沒有參數可掃，沒有顯著性可挑，
跑對跑錯是二值的。`program.md` §2.1 最怕的「為了填滿輪次而找事做」在這條線上
不構成風險——這正是 12 輪／天需要的填充工作。

## Phase A — 資料管線（串流處理，不落地）

`data.binance.vision` 有 aggTrades 日檔。**體積是主要約束**：BTC 單日壓縮後
約數百 MB，GitHub runner 可用磁碟僅約 14 GB，**絕不可先全部下載再處理**。

強制作法：**逐日下載 → 當場聚合成摘要 → 刪除原始檔 → 下一日**。
每分鐘只保留重建 intrabar 路徑所需的最小摘要（到達 high／low 的先後、
區間內往返次數、成交筆數與量），壓縮後每標的每月應在 MB 量級。

- 範圍：先做 **BTC/USDT、ETH/USDT、SOL/USDT × 2024-01 ~ 2024-03**（在 in-sample 內）
- 新腳本放 `research/experiments/`（`research/fetch_klines.py` 對 agent 唯讀，不得修改）
- 產出的摘要 feather **可 commit**（MB 量級）；原始 aggTrades **絕不 commit**

## Phase B — 用真實路徑重跑 Q8 頭條格位，結案 Q9

量出真值落在 `auto` / `reverse` 兩界的哪裡。三種結局都有價值：
落在中間 → 雙序界定有效，Q8 結論的可宣告範圍可放大；
落在界外 → **1m OHLC 方法論對所有網格類工作失效**，這本身是重要發現。

## Phase C — 實測滑價與價差，取代 §3.3 的暫定值

從 aggTrades 算真實 spread 與市場衝擊，回頭修正 `TRADEABILITY_PREREG.md` §3.3。
**修正須走 PR 交人類簽署**（`docs/` 對 agent 唯讀），不得自行改動門檻。
